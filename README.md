# Практическая работа №1. Что программа знает о компьютере

## Цель

Научиться получать сведения о компьютере и операционной системе из программы на C# через класс Environment, понять роль операционной системы как посредника между программой и оборудованием, а также научиться отличать память конкретного процесса от всей оперативной памяти компьютера.

## 1. Информация о компьютере

MachineName: DESKTOP-H5U8H34
UserName: ACER
Дата и время запуска: 16.09.2026 17:17
Программа получила эти значения от операционной системы во время работы. В коде они не записаны. Если запустить программу на другом компьютере, значения будут другими.

## 2. Информация об операционной системе

OSVersion: Microsoft Windows NT 10.0.19045.0
Is64BitOperatingSystem: True
«64-разрядная операционная система». Совпадает с выводом программы. Значит, Environment.OSVersion и Environment.Is64BitOperatingSystem показывают реальные данные системы.

## 3. Логические процессоры

Гипотеза: 4 логических процессора.
Программа вывела: 4.
Диспетчер задач показывает: 4.
Совпадают: да.

Программа и Диспетчер задач показывают одинаковое число логических процессоров. Это число не означает, что в процессоре ровно столько же физических ядер, в Диспетчере задач есть отдельная строка «Ядра», и там число меньше. При технологии Hyper-Threading одно физическое ядро показывается системе как два логических.

## 4. Память процесса

WorkingSet из программы: 14 991 360 байт ≈ 15 МБ.
PID процесса: 12824.
Диспетчер задач для этого PID показывает: 3 300 КБ ≈ 3,2 МБ.
Программа показала ~15 МБ, Диспетчер задач ~3,2 МБ — значения разные. Это нормально: Windows и .NET считают память по-разному. Главное — оба значения относятся к памяти конкретного процесса, а не ко всей оперативной памяти компьютера.

## Дополнительное задание. Мини-монитор системы

### Что делает программа

Выводит сведения о компьютере и ОС, получает через Process.GetCurrentProcess() объект текущего процесса, показывает его PID и WorkingSet64. Между двумя измерениями программа ждёт нажатия Enter.

### Что нового я узнал о классе Process

Process.GetCurrentProcess() возвращает объект текущего процесса. Через него можно узнать PID (свойство Id) и память процесса (WorkingSet64). Это другой способ, чем через Environment.

### Сравнение памяти программы и Диспетчера задач

Значения WorkingSet64 и памяти в Диспетчере близкие, но не идентичные. Windows и .NET считают память по-разному. Оба числа относятся к памяти конкретного процесса, а не ко всей ОЗУ.

### Почему значение памяти может изменяться

.NET во время работы загружает библиотеки, освобождает ненужные объекты и запускает сборщик мусора. Поэтому WorkingSet между измерениями может меняться на несколько мегабайт. Это нормально.

## Контрольные вопросы

1. Программа не хранит имя компьютера в коде, а запрашивает его у операционной системы через класс Environment. ОС хранит эти сведения и возвращает их по запросу.
2. ОС — посредник между программой и оборудованием. Программа обращается к ОС через .NET, а ОС находит нужные сведения и возвращает их.
3. Это значит, что ОС использует 64-битную архитектуру и может работать с большим адресным пространством и большими объёмами ОЗУ, чем 32-битная.
4. Показывает число логических процессоров, которые видит ОС. С числом физических ядер совпадает не обязательно: при Hyper-Threading одно физическое ядро = два логических.
5. WorkingSet — память, используемая только одним процессом (моей программой). Оперативная память компьютера — вся ОЗУ, в которой одновременно работают Windows, браузер, VS Code и другие программы. WorkingSet намного меньше.
6. Потому что значения берутся не из кода, а из ОС того компьютера, где запущена программа. Код одинаков, но системы разные — поэтому и результаты разные.

## Итоговый вывод

Программа на C# не хранит сведения о компьютере внутри себя, а запрашивает их у операционной системы через классы Environment и Process. ОС выступает посредником между программой и оборудованием и возвращает реальные данные о процессоре, памяти, пользователе и версии системы. Из-за этого одна и та же программа без изменений в коде даёт разные результаты на разных компьютерах: в коде написан не конкретный ответ, а запрос к ОС сколько процессоров, какая версия, сколько памяти. Каждый компьютер отвечает по своему, потому что у них разные процессоры, версии Windows, имена и пользователи. Память процесса это только часть ОЗУ, которую использует конкретная программа, а не вся память компьютера.
